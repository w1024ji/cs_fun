# 배열 vs 연결 리스트

코드: `../code/linked_list.c`

## 핵심 비교

| 항목 | 배열 | 단일 연결 리스트 |
|---|---|---|
| 메모리 | 연속 | 노드별 흩어짐(포인터로 연결) |
| 인덱스 접근 | O(1) | O(n) |
| 탐색(값) | O(n) (정렬되면 이진탐색 O(log n)) | O(n) |
| 맨 앞 삽입/삭제 | O(n) (밀어야 함) | O(1) |
| 중간 삽입/삭제 | O(n) | 위치를 알면 O(1), 찾는 데 O(n) |
| 크기 | 고정(정적 배열) | 동적 |
| 추가 메모리 | 없음 | 노드당 포인터 |
| 캐시 효율 | 좋음(지역성) | 나쁨 |

## 면접용 3문장 요약
- 배열은 연속된 메모리에 저장되어 인덱스로 O(1) 접근이 가능하지만, 중간 삽입·삭제는 원소를 이동시켜야 해서 O(n)이다.
- 연결 리스트는 노드가 포인터로 이어져 삽입·삭제가 유연하지만, 임의 접근이 안 되고 포인터 메모리 오버헤드가 있다.
- 조회가 많으면 배열, 삽입·삭제가 잦고 크기가 가변이면 연결 리스트가 적합하다.

## 시험 포인트
- `arr[i]` ≡ `*(arr + i)`: 배열 이름은 첫 원소의 주소.
- 연결 리스트 삭제 시 `prev` 포인터 필요, head 삭제는 특수 처리.
- `malloc` 후 `free` (메모리 누수), 삽입 순서(새 노드의 next 먼저, 그다음 이전 노드의 next).
- 종류: 단일 / 이중 / 원형 연결 리스트. 이중은 prev 포인터가 있어 양방향 순회와 삭제가 쉽다.
- 응용: 스택·큐 구현, 해시 테이블 체이닝.

## 이중 연결 리스트 (`../code/doubly_linked_list.c`)

노드에 `prev`가 추가된 구조. head/tail을 함께 관리한다.

| 항목 | 단일 | 이중 |
|---|---|---|
| 노드 크기 | data + next | data + prev + next (포인터 1개 더) |
| 역방향 순회 | 불가 | 가능 |
| 맨 뒤 삽입 | O(n) (tail 없으면) | O(1) (tail 사용) |
| 노드 포인터를 알 때 삭제 | O(n) (prev를 찾아야 함) | O(1) |

- 삽입·삭제 시 **포인터 4개 갱신**을 빠뜨리기 쉽다(양쪽 노드의 next/prev).
- 경계 처리: 빈 리스트, head 삭제, tail 삭제에서 `head`/`tail` 갱신 누락이 흔한 버그.
- 활용: 브라우저 앞으로/뒤로 가기, 텍스트 편집기 undo/redo, LRU 캐시.
- 면접 한 줄: "이중 연결 리스트는 포인터 메모리를 더 쓰는 대신 양방향 순회와 O(1) 삭제를 얻는다."
